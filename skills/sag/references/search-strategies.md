# 查询策略

## 漏斗范式（省 token、准定位）

每次知识检索按漏斗从宽到窄推进，避免一步跳到 read 浪费上下文：

```
list_sources → list_documents → outline → search/grep → get_chunk/read
```

| 步骤 | 工具 | 产出 |
|---|---|---|
| 1. 确认范围 | `list_sources` | 可用的 source_id 列表 |
| 2. 锁定文档 | `list_documents(source_id)` | 候选 document_id（只看 ready 状态） |
| 3. 定位章节 | `outline(document_id)` | 目标章节的 chunk_id |
| 4. 召回证据 | `search` 或 `grep` | 带编号的证据片段 |
| 5. 溯源原文 | `get_chunk(chunk_id)` 或分页 `read` | 完整原文 |

**原则**: 能用第 4 步回答就用第 4 步，用户追问出处时才进第 5 步。

## search vs grep 决策树

```
用户查询是自然语言问句？
├── 是 → search
│   例："授权流程是怎样的""资料里有没有提到微服务"
│
└── 否 → 是精确字符串？
    ├── 是 → grep
    │   例：编号 INV-2024-0037、函数名 handleAuth、配置项 SAG_MAX_CHUNK
    │
    └── 不确定 → search（语义覆盖面更广）
```

**search 擅长**: 概念、问句、模糊表述、跨段落相关的内容。
**grep 擅长**: 确定字符串、编号、代码片段、专有名词的精确出现位置。

### 组合使用

复杂查询可以两者组合：

1. 先用 search 找到相关主题的范围
2. 再用 grep 精确定位关键术语在该范围内的位置

例：用户问"INV-2024 这批货的审批流程" → 先 search "审批流程" 理解全貌 → 再 grep "INV-2024" 确认该批次的审批记录。

## 引用纪律

回答中的每条外部知识必须标注 `[n]`（n 对应 search 返回的证据编号）。

**正确示例**:
> 授权分为三步：用户发起申请、主管审批、系统记录 [1][3]。审批超时时间为 24 小时 [1]。

**错误示例**:
> 授权分为三步：用户发起申请、主管审批、系统记录。（缺少引用标注）

**追问处理**: 用户追问"这个结论从哪来的""原文怎么说的"时，调用 get_chunk 展示对应 chunk 的完整原文。

## 分页读大文件

`read` 从 offset=1 开始，每次默认 120 行。首行返回「第 a-b 行 / 共 N 行」。

**翻页逻辑**:
```
第 1 次: read(doc_id, offset=1)       → 第 1-120 行 / 共 560 行
第 2 次: read(doc_id, offset=121)     → 第 121-240 行 / 共 560 行
第 3 次: read(doc_id, offset=241)     → 第 241-360 行 / 共 560 行
……
```

**永远不要一次 read 整个大文件**——浪费上下文窗口，且超出 500 行上限会报错。

**先 outline 再 read**: outline 告诉你第 3 章从 chunk_042 开始 → chunk_042 对应第 300 行 → read(doc_id, offset=300)。

## 多步检索示例

### 场景 1：用户问"这份资料讲了什么？"

```
1. list_sources          → 确认范围，取得 source_id
2. list_documents(id)    → 找到目标文档，确认 status = ready
3. outline(doc_id)       → 获取全书大纲
4. get_chunk(chunk_001)  → 读概述章节
   （概述通常在前几个 chunk，不需要逐章读完全书）
```

### 场景 2：用户问"授权流程是怎样的？"

```
1. search("授权流程")    → [1] 授权流程概述 [2] 权限管理 ……
2. 用 [1] 的内容回答，标注引用
3. （用户追问原文）→ get_chunk(chunk_042)
```

### 场景 3：用户问"INV-2024-0037 这个编号在哪里出现过？"

```
1. grep("INV-2024-0037")  → 精确匹配所有出现位置
2. 如有必要 → get_chunk 读其中某个位置的完整上下文
```
