# SAG fnOS Native x86 上线进度

更新日期：2026-08-05。目标是在 fnOS `1.2.0302` 及以上版本，以 Native FPK 交付 SAG x86，入口仅为 fnOS 统一网关 `/app/sag`。

## 当前状态

Native x86 已可在 VMware fnOS 中安装、启用、打开，并可创建信源、上传文档和问答。当前基线包为 `1.5.0-fnos.9`；后续修复包将替代该基线，不与旧包并存。

## 已完成

- Native manifest：`platform=x86`、最低系统版本 `1.2.0302`、依赖 `python312:nodejs_v22`，无 Docker 和 NAS TCP 服务端口。
- 统一网关：页面、API、SSE、WebSocket 通过 `app.sock`；Next 仅监听 `127.0.0.1` 的动态空闲端口。
- fnOS 身份：使用网关提供的 UID、用户名和管理员标记；SAG 不读取密码、不实现注册或 fnOS 登录。
- 隔离：每个 UID 独立 Worker 和 `${TRIM_PKGVAR}/users/<uid>/{meta,engine,uploads,logs}`；内部请求以短期签名绑定 UID。
- P0：VMware x86 已验证 Python 3.12、关键二进制依赖、UDS HTTP 和网关身份 Header。
- 已处理的现场问题：端口 3091 冲突、Native 根入口 404、密钥权限、私有卷父目录遍历权限。

## 本轮修复

- 首 Worker 失败将记录 UID、启动阶段和异常类型，并返回可重试的 `503` 与请求 ID，避免向用户暴露笼统 500。
- `auth_mode=fnos` 时隐藏“退出到启动页”；账号页显示由 fnOS 管理的身份，不提供 SAG 内登录/退出/切换。
- 静态资源、Next 图片优化和附件必须均通过 `/app/sag` 保持同源；发布前以实际资源 URL 验证缓存、内容类型和流式附件响应。

## VMware x86 验收矩阵

| 项目 | 状态 | 验收标准 |
|---|---|---|
| 安装、启用、打开 | 已通过 | 无健康检查错误，可打开聊天页 |
| 创建信源、上传、问答 | 已通过，首请求体验优化中 | 首次操作不显示 500；失败提供可重试提示 |
| 静态图片/附件 | 待复测 | `/app/sag/_next/*`、图标、预览及附件均成功加载 |
| fnOS 身份 UI | 待复测 | 显示 fnOS 用户，不显示 SAG 登录或退出入口 |
| 双账号隔离 | 待操作者执行 | 两个 fnOS UID 的信源、文档、对话互不可见 |
| 升级保留数据 | 待复测 | 升级 FPK 后原 UID 数据仍可访问 |

## 最终验收清单

1. 安装最新 x86 FPK，点击启用和打开。
2. 用第一个 fnOS 账号创建信源、上传文档、完成一次问答，刷新页面确认数据仍在。
3. 检查图标、页面图片、文档预览与附件下载。
4. 确认账号区域显示 fnOS 身份，且没有“退出到启动页”。
5. 后续由操作者用第二个 fnOS 账号重复第 2 步，并确认双方列表、文档和问答互不可见。
6. 升级到后续 FPK 后重复第 2 步确认数据保留。

## 后续阶段

- 完成 VMware 双账号和升级数据保留验收后，将 x86 标记为正式上线。
- ARM 仍暂停；需独立 ARM P0 真机验证、Linux arm64 vendor 构建与完整验收后才发布。
- 后续可将 Next 常驻前端替换为静态前端，从而移除 Node.js 运行时依赖。
